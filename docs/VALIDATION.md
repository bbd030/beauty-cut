## 已确认的镜头边界与运行环境（2026-11-13）

- 按视觉剪辑点划分镜头：切换到另一段拍摄、另一机位、另一场景或独立的产品特写时，考虑设为边界；同机位出现明显剪辑跳切也属于候选边界。
- 同一段连续拍摄中的转头、抬手、移动产品或化妆动作变化，通常不切；不能仅凭字幕、亮度或化妆步骤变化判定换镜头。
- 例如“人物脸部 → 独立口红特写 → 人物涂口红”通常为三个镜头；连续拍摄中先画眉再涂口红通常仍为一个镜头。化妆步骤识别留待后续打标，具体阈值和渐变转场落点在实现与验证时确定。
- 面向大部分普通电脑：优先使用普通 CPU、本地处理，不要求独立显卡；目标兼容 Windows、macOS 和 Linux。跨平台兼容是实施目标，已验证的具体系统须单独记录，不能把目标写成已通过的测试结论。

后续切分测试应覆盖真实剪辑点、同机位跳切以及连续动作/字幕/亮度变化等易混淆情况；目前尚未实现或验证这些切分能力。

验证中修正的问题：

- 初版关闭 `showinfo` 校验和时也失去了必需的均值/离散度信息，改为保留完整统计；缺少信息会失败，不悄悄生成单镜头。

- 真实画面中观察到同一切换附近重复报点，增加小尺寸邻帧签名比较；保留清晰一帧插入的两侧边界。
- 连续手扫镜头造成误报，增加1～3帧模糊遮挡返回原画面的判定，并用合成遮挡加入回归；抽查中两处已确认的手扫误报被抑制，抑制位置保留在本地报告。

设计与局限：

- `detect` 复用既有属性解析和工具进程辅助逻辑，独立完成属性检查与一次完整 CPU 分析解码，不先重复执行功能2的完整解码。仅选择第一条非封面视频轨；不检查音频，不生成预览图或分段视频。
- 算法 `scdet-neighbours-v1`，默认阈值5；320宽度上限用于场景分数、32×32灰度签名用于邻帧判断，补充色度变化。不设置强制最短镜头长度。具体启发式常量由代码/tag固定，报告记录版本和主要配置；本次不是系统性的阈值搜索或独立测试集调优。
- 内部用整数PTS与分数时间基准计算，相对首帧归零；区间为 `[start,end)`，输出秒数最多九位小数。末尾用最后一帧持续时长，缺少可靠时间信息时失败，不用标称帧率或音频长度猜测。分辨率/时间基准改变等输入不保证支持，无法形成完整合法记录时记失败。
- 临时日志及小尺寸签名随视频清理，内存保留逐帧小尺寸分析记录；没有长期保存原分辨率全片。处理超时/损坏时不交付部分镜头，继续下一条视频。
- 渐变、叠化、特效转场不在第一版可靠识别范围。画面抽查仍发现模糊/叠加转场附近可能多报；连续产品运动和细微跳切仍需人工辨别；低细节极短插入可能与遮挡或闪光混淆。抑制规则是启发式，不是语义识别。
- 真实核查是抽样且已用于修正规则，未建立全片真值或独立保留集，未测得全片误切/漏切总数、精确率或召回率。15处零偏移只支持这些选定边界；前后1～2帧是目标，不对所有检测结果作保证。
- 完整报告、临时核查图、人工选定帧号与问题记录只存本地 `outputs/feature3/`；公开提交不包含素材、截图、画面报告、私人笔记或本地绝对路径。功能4的预览与进一步实际切分检查尚未实现。未提交平台评测，没有官方分数。

实现与验证中解决的问题：

- 本机 FFmpeg 9 不再支持旧的 `-filter_script:v`；依据随工具附带的官方文档使用 `-/filter:v` 从文件读取滤镜，避免 Windows 命令行长度限制。
- 旋转合成夹具最初只写旧式元数据，未实际产生旋转信息；改用 `-display_rotation:v:0 90`，同时断言元数据和输出图片宽高，防止假验证。
- 初版把数百个选帧条件相加，真实素材触发 FFmpeg 表达式解析深度限制；改为分层 `if` 条件，并补充240镜头的合成回归。
