自动测试使用临时合成文件，覆盖批量成功、中文和子目录、文件篡改、文件缺失、无效哈希、大小写哈希、UTF-8 BOM、无效 JSON、非对象/空清单、清单不存在或编码错误、路径越界、目录/空路径、文件权限错误、失败后继续，以及 CLI JSON 和退出码 0/1/2。

设计取舍：

- 先验证输入字节，避免后续调试建立在未知素材版本上；该功能独立于视频解码和镜头算法。
- 文件分块读取，避免把整条视频一次性载入内存。
- 单个条目失败形成可读记录，继续检查后续条目；整个清单无效时提前返回退出码 2。
- 使用标准库实现，避免在第一步引入尚未验证的视频依赖。
- 不读取清单目录之外的路径；合成测试不包含招聘素材或画面。

局限：哈希一致仅证明文件与清单一致，不证明视频可播放、镜头边界正确或业务任务已完成；未运行平台评测，因此没有官方分数。基线 tag 为 `baseline-20261113`，后续视频探测与切分应各自形成独立提交及验证记录。

## 已确认的镜头边界与运行环境（2026-11-13）

- 按视觉剪辑点划分镜头：切换到另一段拍摄、另一机位、另一场景或独立的产品特写时，考虑设为边界；同机位出现明显剪辑跳切也属于候选边界。
- 同一段连续拍摄中的转头、抬手、移动产品或化妆动作变化，通常不切；不能仅凭字幕、亮度或化妆步骤变化判定换镜头。
- 例如“人物脸部 → 独立口红特写 → 人物涂口红”通常为三个镜头；连续拍摄中先画眉再涂口红通常仍为一个镜头。化妆步骤识别留待后续打标，具体阈值和渐变转场落点在实现与验证时确定。
- 面向大部分普通电脑：优先使用普通 CPU、本地处理，不要求独立显卡；目标兼容 Windows、macOS 和 Linux。跨平台兼容是实施目标，已验证的具体系统须单独记录，不能把目标写成已通过的测试结论。

后续切分测试应覆盖真实剪辑点、同机位跳切以及连续动作/字幕/亮度变化等易混淆情况；目前尚未实现或验证这些切分能力。
