## 已确认的镜头边界与运行环境（2026-11-13）

- 按视觉剪辑点划分镜头：切换到另一段拍摄、另一机位、另一场景或独立的产品特写时，考虑设为边界；同机位出现明显剪辑跳切也属于候选边界。
- 同一段连续拍摄中的转头、抬手、移动产品或化妆动作变化，通常不切；不能仅凭字幕、亮度或化妆步骤变化判定换镜头。
- 例如“人物脸部 → 独立口红特写 → 人物涂口红”通常为三个镜头；连续拍摄中先画眉再涂口红通常仍为一个镜头。化妆步骤识别留待后续打标，具体阈值和渐变转场落点在实现与验证时确定。
- 面向大部分普通电脑：优先使用普通 CPU、本地处理，不要求独立显卡；目标兼容 Windows、macOS 和 Linux。跨平台兼容是实施目标，已验证的具体系统须单独记录，不能把目标写成已通过的测试结论。

后续切分测试应覆盖真实剪辑点、同机位跳切以及连续动作/字幕/亮度变化等易混淆情况；目前尚未实现或验证这些切分能力。

本次文档同步的回归检查：`python -m unittest discover -s tests -v` 再次 12/12 通过；`python -m beauty_cut verify --manifest aios-shot-materials/SHA256SUMS.json` 再次 4/4 一致，两条命令退出码均为 0。6 份项目文档的四条约定逐条比对一致，`git diff --check` 通过；未修改业务代码，也未新增平台分数或跨平台验证结论。

## v0.2.0：视频属性探测和完整解码验证

日期：2026-11-13。代码版本由 tag `v0.2.0` 固定；本记录与功能代码在同一提交。开发前已另存当前代码快照至被忽略的本地基线目录，原始基线没有覆盖。

环境：Windows / PowerShell 7.6.9 / Python 3.13.2 / FFmpeg、FFprobe 9.0.2 essentials（gyan.dev 构建，来源为 FFmpeg 官方下载页链接）。便携工具保存在本地忽略目录，下载包与发布方 SHA-256 一致且两个工具已实际运行；未修改系统 PATH，没有第三方 Python 依赖。

| 验证 | 实际命令 / 配置 | 实际结果 |
| --- | --- | --- |
| 自动测试，含视频集成测试 | 设置 `BEAUTYCUT_FFMPEG`、`BEAUTYCUT_FFPROBE` 为便携工具路径；`python -m unittest discover -s tests -v` | 36 项全部通过，0 跳过，退出码 0；包含原有 12 项及新增 24 项，其中 8 项是真实视频工具集成测试 |
| 无工具时的测试行为 | 清除上述两个变量，当前 PATH 无视频工具；`python -m unittest discover -s tests -v` | 发现 36 项，28 项通过，8 项集成测试明确跳过，退出码 0；跳过不代表解码通过 |
| 原始素材完整性回归 | `python -m beauty_cut verify --manifest aios-shot-materials/SHA256SUMS.json` | 4/4 一致，退出码 0；此项只验证字节完整性 |
| 真实素材属性与全程解码 | `python -m beauty_cut probe aios-shot-materials/sample-01.mp4 aios-shot-materials/sample-02.mp4 aios-shot-materials/sample-03.mp4 --ffmpeg <本地工具路径> --ffprobe <本地工具路径>`；默认每阶段 600 秒 | 3/3 通过，退出码 0；完整报告仅保存在被忽略的本地 `outputs/probe.json` |

自动测试使用临时生成的合成数据，不依赖题目素材，不访问网络。覆盖中文及空格路径、属性解析、平均/标称分数帧率、缺失属性和未知时长、容器时长回退、旋转角度和编码尺寸、缺失文件/目录/损坏文件/无视频轨、后段损坏但属性可读、多视频轨只选第一条、真实可变帧间隔及解码帧数、零帧/未完成进度、错误日志、工具不可用/版本响应不符、探测与解码超时、失败后继续，以及 CLI JSON 与退出码 0/1/2。进程运行器另用实际子进程检查非零退出诊断和超时终止。

验证中发现并修正一个合成测试素材生成问题：本次 FFmpeg 构建未按旧 `rotate` 标签写入旋转信息，改用 `-display_rotation` 生成带旋转矩阵的测试视频后，旋转信息和编码尺寸检查通过。可变帧间隔测试先独立读取合成视频各帧时间戳，确认间隔确实不同，再比较完整解码的帧数，避免只用文件名或生成参数认定它是可变帧率。

设计取舍与局限：

- 新增独立 `probe` 命令，复用 CLI 和 JSON 汇总结构；`verify` 行为不变。环境问题退出 2；逐文件错误退出 1 并继续。工具版本写入报告以便复查。
- 使用本地 FFprobe 读取属性，FFmpeg CPU 完整解码第一条非封面视频轨至空输出；不做硬件解码，不生成视频、预览图或镜头结果。音频、字幕和额外视频轨不在本功能验证范围。
- 解码遇到错误立即失败，采用无丢帧/补帧的时间处理；未知属性保留 null，不假定固定帧率。工具日志经临时文件收集并限制读入内存的长度；子进程超时后终止。
- 全程成功读取到结束仍不能判断所有内容是否缺失，例如被重新封装为有效文件的截短视频；没有参考原片时不承诺识别这类情况。
- 实际仅验证上述 Windows 环境和 FFmpeg/FFprobe 9.0.2；macOS/Linux 及其他工具版本仍为兼容目标，尚未实机验证。
- 尚未实现镜头检测，不报告镜头准确率；未提交平台评测，没有官方分数。
