# 妆影切片 · BeautyCut

把美妆成品短视频拆分为带起止时间和预览图的镜头清单，为后续打标、检索和重组准备输入。

当前已实现批量素材完整性校验、视频属性探测、完整解码验证、镜头边界检测，以及预览图与本地浏览报告。开发规则见 [AGENTS.md](AGENTS.md)，原始基线见 [docs/BASELINE.md](docs/BASELINE.md)，评测记录见 [docs/EVALUATIONS.md](docs/EVALUATIONS.md)。

原始题目和三条测试视频仅在本地 `aios-shot-materials/` 中保存，不随公开仓库分发。首次使用者需自行取得获准使用的素材。

用户已于2026-11-13确认本地验收成功。[交付说明](docs/DELIVERY.md)汇总了交付内容、复现步骤、设计取舍、开发规则与已知局限；交付版本由 `delivery-20261113` 标签固定。平台评测仍为未提交。

## 已确认的镜头边界与运行环境（2026-11-13）

- 按视觉剪辑点划分镜头：切换到另一段拍摄、另一机位、另一场景或独立的产品特写时，考虑设为边界；同机位出现明显剪辑跳切也属于候选边界。
- 同一段连续拍摄中的转头、抬手、移动产品或化妆动作变化，通常不切；不能仅凭字幕、亮度或化妆步骤变化判定换镜头。
- 例如“人物脸部 → 独立口红特写 → 人物涂口红”通常为三个镜头；连续拍摄中先画眉再涂口红通常仍为一个镜头。化妆步骤识别留待后续打标，具体阈值和渐变转场落点在实现与验证时确定。
- 面向大部分普通电脑：优先使用普通 CPU、本地处理，不要求独立显卡；目标兼容 Windows、macOS 和 Linux。跨平台兼容是实施目标，已验证的具体系统须单独记录，不能把目标写成已通过的测试结论。

## 运行素材校验

需要 Python 3.11 或更新版本；素材校验仅使用标准库，不需要视频工具。从项目根目录运行：

```sh
python -m beauty_cut verify --manifest aios-shot-materials/SHA256SUMS.json
```

清单格式为 JSON 对象：键为相对于清单目录的文件路径，值为 64 位十六进制 SHA-256。支持 UTF-8（含 BOM）、中文与子目录；不读取清单目录之外的文件。原始清单包含题目说明和三条视频，全部检查，不局限于 MP4。

命令向标准输出写入 JSON，含 `schema_version`、`summary` 和逐文件 `results`。每项包含 `file`、`status`、`expected_sha256`、`actual_sha256` 和 `error`。成功时 `error` 为 null；未计算哈希时 `actual_sha256` 为 null。清单整体无效时返回含 `schema_version` 和 `error` 的 JSON。

退出码：`0` 全部一致；`1` 至少一个条目失败（仍检查其余条目）；`2` 清单不可读、格式无效或命令行用法错误。用法错误由 argparse 输出到标准错误。若需保存报告，可将标准输出重定向到本地文件。

此命令只校验文件字节完整性，不验证视频能否解码，也不检测镜头。

## 运行视频探测与完整解码检查

Python 代码仍只使用标准库。此命令另需手动准备 FFmpeg 和 FFprobe：从 [FFmpeg 官方下载页](https://ffmpeg.org/download.html)选择适合系统的构建或软件包，确认两者均可运行。建议使用 FFmpeg 6 或更新版本；本项目实际验证的工具版本见验证记录。Windows 可解压便携版，macOS/Linux 可用系统包管理器安装。程序不自动下载，不上传素材，不要求显卡。

先检查工具，再在项目根目录指定一个或多个本地视频（有空格时加引号）：

```sh
ffmpeg -version
ffprobe -version
python -m beauty_cut probe "video-1.mp4" "video-2.mp4"
```

默认通过 PATH 找工具。便携工具或未加入 PATH 时，使用可执行文件的路径；两个参数需分别指定，例如 Windows：

```powershell
python -m beauty_cut probe "video-1.mp4" "video-2.mp4" --ffmpeg ".local/tools/ffmpeg/bin/ffmpeg.exe" --ffprobe ".local/tools/ffmpeg/bin/ffprobe.exe" --timeout 600
```

上述工具路径是占位示例，替换为实际解压目录。macOS/Linux 同样支持 `--ffmpeg`、`--ffprobe`，使用对应系统的可执行文件路径。工具须由用户安装，项目不分发工具二进制。

报告只向标准输出写 JSON，沿用 `schema_version: 1`、`summary`（`total/passed/failed`）、`results`；新增 `tools` 记录工具版本。每条结果包含：

| 字段 | 含义 |
| --- | --- |
| `file`、`status`、`error` | 输入路径、`passed/failed`、失败原因；成功时 `error` 为 null，失败信息标明 `input/probe/decode` 阶段 |
| `metadata` | 容器、视频编码、编码宽高、时长（秒）、平均/标称帧率、时间基准、旋转角度；属性探测失败时为 null |
| `decode` | `status` 为 `not_run/passed/failed`；`frames` 为成功完成后的实际输出帧数，未成功时为 null |

`metadata` 的具体键为 `container/codec/width/height/duration_seconds/average_fps/nominal_fps/time_base/rotation_degrees`。可选属性缺失、帧率为 `0/0` 等情况保留 null。时长优先用视频轨时长，缺失时用容器时长；宽高是编码尺寸，旋转角度单独报告。平均和标称帧率均不构成固定帧率保证；后续定位镜头须使用实际时间戳，不能仅按帧数除以标称帧率。

只检查第一条非封面视频轨，忽略音频、字幕及其他视频轨。视频按顺序处理，CPU 解码且限制解码线程数为 2；从头读取到结束，出现解码错误即记失败，不写出转码视频或预览图。无视频轨、零帧、文件缺失、工具错误和超时均有明确记录；探测成功后解码失败仍保留属性。输入限本地普通文件，工具的输入协议限制为本地文件，不能传 URL 或网络播放列表。

`--timeout` 默认 600 秒，限制每条视频的属性探测和解码各自的最大时间；工具启动检查每个最多 10 秒。超时会终止对应进程并继续下一条视频；慢电脑或长视频可适当调大，须为有限正数。

退出码：`0` 所有视频通过；`1` 至少一条失败且已继续其余条目；`2` 工具缺失/无法启动、无效超时或命令行错误。环境配置错误输出含 `schema_version/error` 的 JSON；命令行用法错误仍由 argparse 输出到标准错误。`verify` 与 `probe` 分别运行，不自动串联，也不会把哈希校验通过计入解码通过。

保存本地报告可先创建被忽略的 `outputs/`，再将标准输出重定向到 `outputs/probe.json`。不要把报告或素材画面加入公开仓库。

解码通过表示本次工具成功读取到文件结束，不代表音频检查、镜头检测或官方评测通过；没有参考原片时，不能识别所有被重新封装成有效文件的截短内容。命令选项依据 [FFmpeg 文档](https://ffmpeg.org/ffmpeg.html)和 [FFprobe 文档](https://ffmpeg.org/ffprobe.html)。

## 运行镜头边界检测（功能3）

一次指定多个本地文件，无需先执行 `verify` 或 `probe`：

```sh
python -m beauty_cut detect "video-1.mp4" "video-2.mp4" --threshold 5 --timeout 600
```

未配置 PATH 时，像 `probe` 一样分别传入 `--ffmpeg` 和 `--ffprobe` 的工具路径。可先创建 `outputs/`，再将标准输出重定向到 `outputs/detect.json`。命令不自动创建目录，不覆盖原视频，不导出分段视频或预览图。

仅需 Python 标准库和本地 FFmpeg/FFprobe，CPU 运行，不上传画面。功能3实际验证的工具版本为 FFmpeg/FFprobe 9.0.2；要求 FFmpeg 提供 `split/scale/format/scdet/metadata/showinfo` 滤镜、`-enc_time_base demux` 和 `showinfo` 整数帧时间及持续时间。旧版本未验证，缺少必要能力时明确报错，不以标称帧率推算代替真实时间。

### 判断方法和范围

优先检测直接切换和明显同机位跳切，不识别化妆步骤。逐帧解码第一条非封面视频轨，保持原有帧序，不抽帧、不按固定帧率重采样。画面分析宽度不超过320，另生成每帧32×32灰度签名用于邻帧比较；签名是临时分析数据，不是交付预览图。旋转信息单独记录，检测使用编码方向，与功能2一致。

以 FFmpeg `scdet` 的画面变化分数为基础，补充较强的色度变化，降低相近亮度、不同颜色切换的漏检。分数达到 `--threshold` 才成为候选；默认5，范围 `(0,100]`，越低越敏感。这个分数不是正确概率，也不是官方评分。

结合前后帧统计和小尺寸签名，抑制返回相近原画面且主要是亮度偏移的一帧闪光，以及细节明显减少、1～3帧内回到原画面的模糊遮挡。`analysis.transient_suppressed_frames` 记录这些位置以供复核。相邻两次变化若表现为“旧画面→新画面→几乎相同的新画面”，保留主要变化；清晰的“旧画面→一帧插入→旧画面”保留两个边界。不设置一刀切的最短镜头长度。

这些是可复现的启发式规则，不能可靠区分所有大幅动作和跳切。渐变、叠化、特效转场不在第一版可靠识别范围；连续移动产品可能误切，细微跳切可能漏切，相似的一帧画面可能与闪光混淆。每条成功结果均附人工核查提示。成功状态只表示处理完成，不表示镜头全部正确。

### 报告与时间约定

JSON 沿用 `schema_version: 1`、`tools`、`summary` 和 `results`；新增 `config` 保存算法版本、阈值和分析尺寸。每条结果包含：

| 字段 | 含义 |
| --- | --- |
| `file/status/error` | 输入、`passed/failed`、分阶段错误；成功时错误为 null |
| `metadata` | 沿用功能2的视频属性；后续分析失败仍保留已读取的属性 |
| `analysis` | 分析帧数、原始首帧时间 `origin_seconds`、实际覆盖时长、镜头数量、边界位置与依据、闪光/遮挡抑制帧号；失败为 null |
| `shots` | 镜头清单；失败为空数组，不交付部分结果 |
| `warnings` | 核查提示与算法局限 |

每个镜头含 `id`（从1开始）、`start_seconds/end_seconds/duration_seconds` 和 `start_frame/end_frame_exclusive`（从0开始）。`analysis.boundaries` 中的 `frame` 是新镜头第一帧，另有 `time_seconds/strength/reason`。时间以视频轨首帧为0；相对原始时间定位时加回 `origin_seconds`。与播放器包含音频或编辑列表的整体时间线是否一致，需要单独核对。

区间采用 `[开始,结束)`，即包括开始、不包括结束，边界帧属于后一个镜头。内部用整数时间戳和时间基准的分数计算，输出秒数最多九位小数；输出位数不代表算法准确率。相邻镜头复用同一边界值，无重叠、无空隙，覆盖全部分析帧。末尾用最后一帧时间加其持续时长，不采用音频长度或容器时长凑齐。时间戳缺失、重复/倒退、末帧持续时长不可用时记失败，不猜测。没有检测到边界时输出覆盖全片的一个镜头。

`--timeout` 默认600秒，分别限制每条视频的属性探测和完整分析进程；工具启动/能力检查各最多10秒。单条失败继续；退出码 `0` 全部完成，`1` 有视频失败，`2` 整体配置/工具不可用或命令行用法错误。机器报告写标准输出，命令行用法错误由 argparse 写标准错误。日志和每帧签名使用临时文件，完成或失败后清理；内存保留当前视频的小尺寸签名和时间记录，随帧数增长，不把原分辨率全片载入内存。

功能3不先运行一次功能2的完整解码；分析本身检查完整解码、结束标志、帧数与签名数量一致，避免正常检测重复解码。`verify`、`probe` 行为不变。

### 如何检查

合成视频提供已知边界，检查误切、漏切及实际帧时间；真实素材需另行查看画面，重点检查边界前后连续帧和没有被切开的长片段。直接切换以新镜头第一帧定位，前后1～2帧为目标；目前只完成有限真实边界抽查，没有整片人工真值，不报告全片精确率或召回率。实际验证数量、抽查范围和发现的问题见 [验证记录](docs/VALIDATION.md)。

## 生成镜头预览与本地报告（功能4）

一次批量指定本地视频和输出目录，无需预先执行其他命令：

```sh
python -m beauty_cut preview "video-1.mp4" "video-2.mp4" --output-dir outputs/feature4
```

未配置 PATH 时，使用 `--ffmpeg` 和 `--ffprobe` 分别指定本地工具，例如 Windows：

```powershell
python -m beauty_cut preview "video-1.mp4" "video-2.mp4" --output-dir outputs/feature4 --ffmpeg ".local/tools/ffmpeg/bin/ffmpeg.exe" --ffprobe ".local/tools/ffmpeg/bin/ffprobe.exe" --threshold 5 --timeout 600
```

工具路径是占位示例，替换为实际路径。依赖沿用 Python 标准库及 FFmpeg/FFprobe；实际验证版本为 9.0.2。另需 `select/showinfo/scale/setsar`、JPEG 编码及 `-/filter:v` 从文件读取滤镜参数的能力；旧工具版本未验证。程序不下载工具、不使用云服务、不要求显卡。

### 如何查看和核查

1. 命令向标准输出返回 JSON，`report_file` 给出本次报告的绝对路径。
2. 用浏览器打开对应 `index.html`，进入各条成功视频的报告。报告离线使用，不需要 HTTP 服务、账号或网络。
3. 镜头卡片显示编号、起止时间、时长和中间帧。点击“检查开始边界”，展开边界前后各最多两帧；绿色边框为新镜头第一帧。帧号从0开始。
4. 首次打开报告时，“播放此镜头”按钮默认禁用，呈灰色且无法点击。先在报告顶部点击“选择本地原视频”，选择与报告对应的文件；视频加载成功且支持镜头定位后，按钮才会启用。文件由浏览器本地读取，不上传、不复制进报告；每次重新打开报告，都需要重新选择原视频。
5. 使用播放器控制条连续观看全片，重点检查长镜头内是否漏切。边界图片用来逐帧检查；播放器定位和自动停止只提供近似位置，不能替代逐帧图片。

文件名和字节大小不符时拒绝加载；匹配不构成内容一致性证明。浏览器不支持编码、读取失败、时间范围异常时显示提示。无法取得可靠容器起点、存在多条非封面视频轨时停用镜头定位，仍可查看图片；能解码的文件可手动播放。如果选择文件后按钮仍无法点击，请查看报告顶部播放器区域的状态提示，按提示检查文件或播放兼容性。不保证所有浏览器与所有容器/编码均支持。当前只验证 Windows 上 Chrome 157 的本地文件播放，详见验证记录。

播放偏移量由“视频首帧时间减容器起点”计算。音频先于视频的合成案例已验证元数据偏移；复杂编辑列表、不同浏览器的时间线处理仍可能偏移。页面明确提示核对，不承诺浏览器定位精确到帧。短镜头播放可能因浏览器事件间隔超过结束位置，逐帧归属以图片与清单为准。

### 图片规则与数据流

检测复用功能3，默认算法和阈值不变，不先重复执行功能2的完整解码。单条检测完成后，在其精确帧时间记录仍可用时选择图片，然后进行第二次顺序解码集中抽图。去除重复目标帧，不为每张图重新读取全片；抽图使用分层选择表达式，避免数百个目标超过 FFmpeg 解析深度。

预览选取镜头时间中点所在的实际帧，保证在该镜头 `[start_frame,end_frame_exclusive)` 内；单帧镜头使用唯一一帧。依据真实时间戳选取，不用标称帧率换算，也不以中间帧号替代时间中点。边界前后帧按实际帧序选择，短镜头附近标明每帧的镜头归属。抽图时核对实际输出帧时间戳、图片数量与非零大小，不符则失败。

图片为 JPEG、最长边不超过640像素、不主动放大小图，保持显示比例（偶数尺寸会有像素级取整），由 FFmpeg 应用旋转信息。画面可能模糊、遮挡、过曝或包含转场，不自动挑选“最好看”的帧；这是第一版已确认的取舍。检测仍使用编码方向，旋转显示不改变帧编号。

每次运行自动新建唯一目录，结构如下：

```text
outputs/feature4/run-日期时间-唯一后缀/
    index.html                 批次首页
    results.json               完整机器报告
    video-001/index.html       单视频报告（仅完整生成成功时存在）
    video-001/images/*.jpg      去重后的预览和边界图片
```

同名视频使用独立编号，重复运行不覆盖旧报告。网页内嵌样式、脚本和数据，图片使用相对路径，无远程资源；移动结果时应保留整个运行目录。原视频需另行保留。输出和含画面的报告仅限本地，使用被忽略的 `outputs/` 或 `.local/`，不得提交公开仓库。

JSON 沿用 `schema_version/tools/config/summary/results`，另含 `report_file`。`config` 增加预览选帧方法、边界帧数、图片尺寸；每条结果新增 `detection_status/preview_status/report/source/playback/boundary_previews`，每个成功镜头新增 `preview`（`frame/time_seconds/image`）。图片路径相对于对应视频报告；`report` 相对于批次首页；`source` 保存文件名和字节大小。时间和帧区间仍沿用功能3约定。

### 失败与退出码

单条失败继续。检测失败时 `preview_status` 为 `not_run`；检测成功但图片或报告生成失败时，保留原镜头时间清单、`detection_status: passed`，总体记失败，不交付部分图片链接。错误带阶段名。逐视频临时目录在正常结束或异常展开后清理；输入在抽图期间发生可观察的大小/修改时间变化时拒绝交付。此检查不是对并发修改的完整锁定，处理时应保持输入不变。

输出目录提前创建并检查可写性。处理中断或整体配置/发布失败可能留下带 `INCOMPLETE.txt` 的目录；这类目录不代表本次报告成功完成，应按错误修复后重新运行。旧运行目录不修改。硬终止可能遗留工作目录；不提供断点续跑。

`--timeout` 默认600秒，分别限制每条视频的属性探测、完整分析、抽图和播放时间信息探测进程，不是整批总时限。退出码 `0` 全部完成，`1` 至少一条失败，`2` 整体配置、工具或报告发布错误；命令行用法错误仍由 argparse 写标准错误。完成不代表镜头全部正确，不生成独立片段视频，也不提交平台评测。

## 测试

```sh
python -m unittest discover -s tests -v
```

测试在临时目录中生成合成数据，不需要题目素材、网络或云服务。单元测试不依赖 FFmpeg；视频集成测试需同时找到 FFmpeg/FFprobe，否则明确跳过。工具可以位于 PATH，也可通过环境变量 `BEAUTYCUT_FFMPEG`、`BEAUTYCUT_FFPROBE` 指定（仅供测试，业务命令使用上述参数）。不要把跳过集成测试说成解码验证通过。最新验证记录见 [docs/VALIDATION.md](docs/VALIDATION.md)。
